# Changelog

pyrailworks follows [Semantic Versioning](https://semver.org/). Before 1.0, a minor version (0.x.0) may change the public API and a patch version (0.x.y) doesn't. Each release is a `vX.Y.Z` tag with a GitHub release, which publishes it to PyPI.

## 0.3.0 (unreleased)

### Uses the railworks `/v2` API

railworks no longer republishes Iarnród Éireann's notice text ([railworks ADR 0003](https://github.com/Irishsmurf/railworks/blob/main/docs/adr/0003-publish-structured-facts-not-upstream-text.md)), so it added `/v2` and is retiring the `/v1` routes that served the text. pyrailworks 0.3.0 calls `/v2` for every request.

**Upgrade before 1 December 2026.** From **2026-12-01T00:00:00Z** (midnight in Dublin), `/v1/notices`, `/v1/notices/{id}`, `/v1/notices/{id}/raw` and `/v1/health` answer `410 Gone`. In pyrailworks 0.2.x and earlier, `list_notices()`, `get_notice()`, `get_notice_raw()` and `get_health()` stop working on that date. Stations, station days, changes and calendar feeds keep working in every version.

Ids, cursors, query parameters, ETags and errors are the same under `/v2`. Most code only needs the upgrade. What changed:

| 0.2.x (`/v1`) | 0.3.0 (`/v2`) | In 0.3.0 |
|---|---|---|
| `WorksNotice.heading` | `WorksNotice.title` | `heading` still works: a deprecated alias of `title` |
| `WorksNotice.detail` (a string) | `WorksNotice.summary` (a list of lines, in lists too) | `detail` still works: `summary` joined with newlines, deprecated |
| `get_notice_raw(id)` | `get_notice(id).revisions` | Still works, deprecated: it returns the revisions, with `html` always `None` |
| `Revision.html` | (none) | Always `None`, deprecated |
| `NoticeRef.heading` (`held_notices`, `low_confidence`) | `NoticeRef.title` | `heading` still works: a deprecated alias of `title` |
| `DaySection.heading` | (none): Day Sections have `days` only | Removed |
| `WorksSegment.quote`, `.clause` | (none) | Removed |
| `Effect.quote` | (none) | Removed |
| `ServiceAlteration.quote` | (none) | Removed |
| `ServiceAlteration.stations` (as written) | `ServiceAlteration.station_codes` | Removed |

- `title` and `summary` are generated by railworks from the facts, and may be reworded. Display them, but don't parse them: use `days`, `starts_on` and `ends_on` for dates.
- `WorksSegment.from_`/`to` and `Effect.from_`/`to` are now names from railworks' station list, and `None` when the place isn't known. A Service Alteration's `origin` and `destination` are named from its codes, and the `*_codes` fields are always there.
- The deprecated aliases raise `DeprecationWarning` and are flagged by type checkers that understand `@deprecated` (mypy with `--enable-error-code deprecated`, pyright). They'll be removed in a later minor version.
- Fields with no `/v2` successor are removed rather than returning empty text, so a type checker finds every use. The text is no longer published anywhere; for it, see [irishrail.ie](https://www.irishrail.ie/).
- There's no option to call `/v1` from 0.3.0. If you need `/v1`'s verbatim text until the Sunset, stay on `pyrailworks<0.3`.

### Added

- **`ApiDeprecationWarning`**: when a response carries a `Deprecation` (RFC 9745) or `Sunset` (RFC 8594) header, the client warns, with the route's `path`, `deprecated_at`, `sunset` and `successor`. It's a `FutureWarning`, so Python shows it by default.
- **`GoneError`** (410), with the `successor` the API names. A 410 used to raise a plain `ProblemError`.
- New fields: `WorksNotice.withdrawn_reason`, `Revision.extended`, `ChangeEvent.extended` and `.withdrawn_reason`, and in `Health`: `needs_review`, `empty_detail`, `no_stations` and each held notice's `reason`. Their enums (`WithdrawnReason`, `HeldReason`, `ReviewReason`) are open, like every other.
- `pyrailworks.API_VERSION` (`"v2"`).
- `typing_extensions` is now a direct dependency (pydantic already required it).

## 0.2.0 (2026-10-01)

Tolerates API additions.

- **Open enums:** every response enum subclasses `OpenEnum`. An unknown value parses as an `UNKNOWN` member that keeps the raw value, still compares equal to the string, and has `is_known == False`.
- **`pyrailworks.__version__`**, and the `User-Agent` reports it (it was hard-coded to `pyrailworks/0.1.0`).
- Integration tests read `RAILWORKS_BASE_URL`, so the railworks repository runs them against every change to the API.
- Nightly CI checks compatibility with the live API.

Backwards compatible with 0.1.x.

## 0.1.1 (2026-09-24)

- Unit tests and live integration tests are separate (`pytest -m "not integration"` and `pytest -m integration`).
- A PyPI publishing workflow.

## 0.1.0 (2026-09-24)

- First release: sync and async clients for the railworks `/v1` API, Pydantic models, and RFC 9457 errors as exceptions.
